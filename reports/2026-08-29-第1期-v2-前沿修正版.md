# AI 新职业雷达｜第 1 期 v2：前沿修正版

> 观察日：2026-08-29
> 地区：全球前沿信号 + 中国可进入样本
> 状态：人工研究快照，不是实时岗位流
> 纠偏：本版保留初版作为历史记录，但替代初版在网站与哨塔中的展示排序。

## 先说结论

初版把“对良当前更适合”排在了“职业到底够不够新”前面，所以医疗评测、通用模型测试、AI 产品运营等成熟任务占据首页，而 FDE 被埋在第 7 位。这不符合“新职业雷达”的目标。

本版改为两套互不混淆的判断：

1. **雷达排序**：最近 6—12 个月是否出现新任务组合、跨雇主重复、行业细分、地区扩散或团队层级。
2. **良的适配**：良现在能否进入，只作为第二标签，不再决定职业是否进入第一屏。

因此，FDE / AI Deployment Engineer 升到第 1 位。不是因为 FDE 这个词刚被发明，而是因为 AI 版本的 FDE 正从少数公司用语扩散成跨公司、跨地区、跨行业和带管理层级的职业族群。

## 1. FDE / AI Deployment Engineer

**为什么现在算新信号**

- LinkedIn 2026-08-18 的美国职位研究把 Forward Deployed Engineer 列为其口径下第三常见的 AI 职业，并说明统计使用 2023—2026 年美国职位数据。[LinkedIn 研究](https://news.linkedin.com/2026/new-linkedin-research-finds-women-account-for-just-26-percent-of-ai-hires-as-ai-jobs-surge)
- OpenAI 当前搜索页列出 22 个 forward-deployed 相关岗位，已细分到医疗、法律、政府、半导体以及美国、亚洲、澳洲和中东等地区。[OpenAI 当前职位](https://openai.com/careers/search/?q=forward+deployed)
- Anthropic 当前 Applied AI 团队同时列出 FDE、Applied AI Architect、Applied AI Engineer 和 Technical Deployment Lead；Scale 已招聘 FDE 团队负责人，说明它不再只是单个猎奇头衔。[Anthropic 当前职位](https://www.anthropic.com/careers/jobs?hsLang=en-us)；[Scale FDE 负责人](https://scale.com/careers/4690504005)

**职业边界**

FDE 负责从客户发现、范围界定、架构和编码，到评测、生产上线、采用和反馈产品路线的完整闭环。它比解决方案架构师更强调亲自构建，比普通软件工程师更贴近客户与业务结果。

**反证**

FDE 不是“会用 AI 工具”的新手岗。OpenAI 通用 FDE 通常要求 5 年以上经验，医疗 FDE 要求 6 年以上并理解医疗系统；Scale 也强调强编码和端到端交付。[OpenAI FDE](https://openai.com/careers/forward-deployed-engineer-%28fde%29-seattle-seattle/)；[OpenAI Healthcare FDE](https://openai.com/careers/forward-deployed-engineer-%28fde%29-healthcare-sf-san-francisco/)；[Scale FDE](https://scale.com/careers/4593571005)

**对良**

列为一号市场信号，但不是当前主投。更现实的迁移链是 AI 产品 / 评测 / 解决方案助理 → 独立完成 PoC 与验收 → 客户侧部署负责人 → FDE。

## 2. AI Product Engineer / AI 产品工程师

**为什么现在算新信号**

- 百度 2026-07-21 直接招聘“AI 产品工程实习生”，要求重度使用 AI Coding，把想法快速变成可用功能，同时负责产品体验、交互细节和完整闭环。[百度 AI 产品工程实习](https://talent.baidu.com/jobs/detail/INTERN/eccb3218-409a-4157-98a6-895b733266cd)
- OpenAI 当前 Agent 职位中出现 Product Engineer, Full Stack - Agents，并同时存在 Enterprise AI Platform、GTM Innovation 等 Product Engineer 细分。[OpenAI Agent 职位](https://openai.com/careers/search/?q=agent)

**职业边界**

它不是传统 PM，也不是只按需求写代码的工程师；核心产出是用 AI Coding 快速完成“需求判断 → 原型 → 可用功能 → 用户反馈 → 再迭代”。

**反证**

中国同名岗位仍少，可能长期以产品实习、独立开发者、增长工程或全栈产品工程等名称存在。不会基础开发、调试和部署时，不能只靠 Vibe Coding 冒充工程能力。

**对良**

这是非常值得补的方向，但当前归 stretch。现有本地 AI 产品可以作为起点，下一步要证明自己能解释代码、独立定位问题并完成部署验收。

## 3. Agent Evals Product / Agent 策略 PM

**为什么现在算新信号**

- 百度 2026-08-17 的 DuMate 策略 PM 实习生要求搭建执行类 Agent 评测体系，制定长程任务测试，优化任务完成率、记忆连贯性和成本，并负责 Office、浏览器自动化等内置 Skill 的策略与复盘。[百度当前实习列表](https://talent.baidu.com/jobs/list?recruitType=INTERN)
- 同一公司 2026-07-21 已出现“评测产品实习生”，任务几乎围绕 Agent 长程评测与 Skill 策略展开，说明它不是普通产品经理临时加一句 AI。[百度评测产品实习](https://talent.baidu.com/jobs/detail/INTERN/a7487847-e649-4b60-96cf-faa90f6f8b34)

**职业边界**

它负责定义 Agent 应该完成什么任务、如何量化成功、哪些 Skill 该内置、失败如何归因和下一轮策略怎么改；不主要负责写底层评测框架。

**反证**

当前中国一手证据主要来自百度，仍可能是组织内部专用命名，所以列 frontier，不冒充全国放量。

**对良**

这是本版最值得良直接关注的新入口。临床任务拆解、验收标准、失败分类和可验证工作流都能迁移，但作品必须从“回答对不对”升级到多步任务的完成率、成本、记忆和异常恢复。

## 4. Agent Evaluation Engineer / Environment Builder

**为什么现在算新信号**

- 百度“Agent 评估工程师实习生”把记忆、规划、工具调用、反思、负样本归因、LLM-as-a-judge 和 Agent Benchmark 组合成独立岗位。[百度 Agent 评估工程师](https://talent.baidu.com/jobs/detail/INTERN/a0bbc449-854f-421c-bfaf-1a5be906f86e)
- OpenAI 当前 Agent 岗位已出现 Frontier Evals & Environments，Anthropic 同时存在 Model Evaluations、Evals Infrastructure 和 Universes / Environments Infrastructure 等岗位。[OpenAI Agent 职位](https://openai.com/careers/search/?q=agent)；[Anthropic 当前职位](https://www.anthropic.com/careers/jobs?hsLang=en-us)

**职业边界**

它不只是测试模型回复，而是构造 Agent 可执行的任务环境、自动 grader、失败轨迹、回归实验和 benchmark。

**反证**

岗位通常要求 Python、统计、实验设计和工程框架；低代码评测表只能证明产品思维，不能替代工程能力。

**对良**

列为 stretch。先从 Agent Evals Product 或医疗 AI 评测进入，再补 Python 自动化、日志分析和最小评测 harness。

## 5. Agent Post-Training Engineer / Researcher

**为什么现在算新信号**

OpenAI 的 Agent Post-Training 已拆到 Context、Connectors、Computer Use、Personality、Artifacts、API & Power Users、Frontier Evals & Environments 等细分；Anthropic 也招聘 Production Model Post-Training。[OpenAI Agent 职位](https://openai.com/careers/search/?q=agent)；[OpenAI Context Research](https://openai.com/careers/agent-post-training-context-research-san-francisco/)；[Anthropic 当前职位](https://www.anthropic.com/careers/jobs?hsLang=en-us)

**职业边界**

它把产品行为问题变成训练数据、环境、grader、奖励信号和训练实验，直接决定 Agent 学会什么能力。

**反证**

这是前沿实验室的高门槛研究工程岗位，不代表大众就业会同步增长。

**对良**

只观察，不按当前求职方向投入完整训练栈。

## 6. Applied AI Architect / Applied AI Engineer

**为什么现在算新信号**

Anthropic 当前 Applied AI 团队有 20 个职位，覆盖商业、政府、行业、合作伙伴、企业技术、安全与多个国家；OpenAI 也同时招聘多类 Applied AI Architect / Engineer。[Anthropic 当前职位](https://www.anthropic.com/careers/jobs?hsLang=en-us)；[OpenAI 当前职位](https://openai.com/careers/search/?trk=public_post-text)

**职业边界**

它比 FDE 更偏架构、技术咨询、平台能力与可复用方案；比传统售前更要求理解模型行为、评测和生产边界。

**反证**

许多样本偏资深、面向企业大客户；标题可能与 Solutions Architect 长期并存。

**对良**

列为 stretch。可先积累医疗 AI 场景发现、方案表达、PoC 和验收，再向医疗 Applied AI / Solutions 迁移。

## 7. AI Success Engineer / 领域 AI 成功工程师

**为什么现在算新信号**

OpenAI 当前职位把 AI Success Engineer 细分到教育、政府、医疗与生命科学，并在多个地区招聘；同时存在 Biosciences AI Support Engineer。[OpenAI AI Success 搜索](https://openai.com/careers/search/?q=ai+success)；[OpenAI 领域岗位列表](https://openai.com/careers/search/?locationId=6252b4ed-714d-469a-a970-7a13101bac9d)

**职业边界**

它对客户采用、工作流效果、使用障碍和业务结果负责，通常比 FDE 少写核心系统，比传统客户成功更懂模型、API 和评测。

**反证**

目前强证据主要来自 OpenAI，且不少岗位要求多年技术支持或客户成功经验。

**对良**

这是医疗背景可能产生复利的中期方向。当前先找 AI 产品支持、医疗解决方案、产品运营和验收岗位，不直接把自己包装成资深 Success Engineer。

## 8. Agentic Risk / Safeguards Analyst

**为什么现在算新信号**

OpenAI 的 Agentic Risk Analyst 明确管理 Agent 在自治、多步执行、工具、记忆、连接器、computer use 和多 Agent 工作流中的现实风险；Anthropic 的 Safeguards 已分化到研究、基础设施、数据、红队与领域风险。[OpenAI Agentic Risk Analyst](https://openai.com/careers/agentic-risk-analyst-san-francisco/)；[Anthropic 当前职位](https://www.anthropic.com/careers/jobs?hsLang=en-us)

**反证**

OpenAI 样本通常要求 7 年以上安全、风控、调查或信任安全经验；中国初级岗位证据不足。

**对良**

只观察。在医疗评测作品中加入风险分级、升级机制、适用边界和高风险失败案例即可。

## 9. Agent Identity & Trust Designer

**为什么现在算新信号**

OpenAI 当前产品设计岗位已经把人—Agent、Agent—Agent 的身份、授权、权限、确认和信任模型写成明确职责。[OpenAI Agent Identity 设计](https://openai.com/careers/product-designer-identity-san-francisco/)

**反证**

目前只有单一强样本，可能只是身份产品设计师的新任务，而不会形成独立职业。

**对良**

不转轨，但在设计医疗 Agent 时值得加入“谁授权、能做什么、何时必须人工确认”的交互证据。

## 10. Agent Product Manager / Workflow Product

**为什么现在仍算扩散**

百度近期岗位要求 Agent 工作流、模型边界、异常处理、Vibe Coding 和产品数据；OpenAI 当前同时招聘 API Agents 产品经理。[百度 AI Agent 产品](https://talent.baidu.com/jobs/detail/INTERN/d896e43f-94b7-4eb5-93af-d99a24896997)；[OpenAI Agent 职位](https://openai.com/careers/search/?q=agent)

**反证**

“AI 产品经理”已经不是新词；只有真正对 Agent 的工具调用、多步任务、异常处理和评测负责的岗位才进入本簇。

**对良**

直接关注。作品要明确展示 Agent 与普通聊天机器人的区别。

## 11. 医疗 AI 评测与领域数据质量

这是良的差异化入口，但不再冒充最前沿职业。其价值来自临床标准、循证证据、测试集、风险分级和模型反馈，而不是“医学标注”头衔。它留在雷达，是因为医疗 FDE、生命科学 AI Success、Biosciences Support 和医疗模型评测正在发生汇合。

对良的动作仍是完成一份无患者隐私的医疗 AI 评测包，并逐步把它升级成多步 Agent 医疗工作流验收。

## 12. 通用 AI 产品运营 / RAG 知识治理

需求真实，但已成为基线岗位。只有当职责包含模型效果、来源追溯、Agent 评估、用户反馈和迭代闭环时才值得投；仅维护 FAQ、上传文档或换皮增长的不再算新职业。

## 13. 独立提示词 / 泛训练师 / 模板数字人

统一移入 cooling：

- Prompt 仍是重要技能，但正被产品、工程、运营、设计和研究岗位吸收。
- 基础标注与泛训练任务容易商品化和自动化。
- 模板数字人批量生产供给同质化。

除非出现领域标准、质量责任、评测闭环或产品所有权，否则不作为职业定位，也不为单一头衔买证。

## 现在 / 触发后 / 暂不做

### 现在

1. 监测关键词从旧的“AI 训练师 / 提示词工程师”改成：FDE、Forward Deployed、AI Deployment、AI Product Engineer、Agent Evals、Agent Evaluation、Environment Builder、Agent Post-Training、Applied AI Architect、AI Success、Agentic Risk。
2. 良的近期主线只保留两个直接入口：Agent Evals Product / Agent 产品，以及医疗 AI 评测。
3. 把现有项目改造成可核验作品：任务定义、工具权限、失败轨迹、评测指标、人工确认、成本和结果。

### 触发后

- 中国 8 周内出现至少 3 家独立雇主的 AI 产品工程、Agent 评测产品或 AI Success 初级岗位时，上调为直接主投。
- 长三角出现医疗 FDE / 医疗 AI Success / 医疗 Agent 产品的实习或 0—1 年岗位时，单独建立投递清单。

### 暂不做

- 不因为 FDE 热就暂停求职、从零补完整全栈。
- 不把单一公司自创标题当成已经成型的职业。
- 不用官方新职业目录决定首页排序。
- 不接账号、Cookie 或招聘平台自动采集；本版仍是人工研究快照。

## 本版可证伪条件

- 如果未来 8—12 周 FDE、AI Product Engineer、Agent Evals 等职位只在同一批公司内部换名、没有新增雇主和地区扩散，应降级。
- 如果中国样本持续只要求资深工程师、没有 junior 入口，则它们仍是“市场前沿”，不是“良当前机会”。
- 如果 Agent 产品退回普通聊天、内容生成或提示词维护，缺少工具调用、环境、评测与结果责任，则不再算新职业。

## 2026-08-29 追加说明：两个展示版本

本报告的市场排序不变。网站与哨塔从本次更新起使用同一证据快照提供两个展示版本：

- `市场前沿版`：继续按新颖度和近期扩散排序，FDE 排名第 1。
- `良的适配版`：按个人可进入性排序，前 6 位依次为医疗 AI 评测、Agent Evals Product、Agent Product Manager、AI Success Engineer、AI Product Engineer、通用 AI 产品运营 / RAG。

适配排序不声称这些职业的市场规模更大，也不更改职业簇的新颖度、需求阶段或置信度。站内手动刷新只检查 5 个固定公开信源并生成候选状态；候选命中在人工核验前不得进入本报告结论。
